ACCEPTANCE DETAILS:
- dispatch/runtime-guards.ts: the window of an order's route is the host's own figure first, else the routing table's contextTokens for the route (read through the routing service; a failing read is reported and means "not known", not "missing"). A figure that is not a window (not a positive integer: 0, negative, fractional, NaN, infinite), from the host or the routing table, is no window; a host figure that is none asks the routing table. The same two-step is used for a route move's rebuild (C07g's check).
- With neither figure the first call and a stored-conversation resume are refused, never admitted unchecked: ContextEnforcementService opens (or returns the one already open) a `context_overflow` blocker on the task naming the route (quoted) and both places the window can be set; the refusal carries `retryable: false` so the local worker does not spend its one compaction on it.
- A stored conversation is judged before it is carried even when the embedder passes no storedTokens: its size is read from the worker package's checkpoint shape.
- The C07l todo case in dispatch/first-call-hops.test.ts (a first call of a million tokens on a route of unknown window) passes and loses its todo; shown through startController (api/).

CONTRACT (the acceptance tests check exactly these; names, fields and wording here are binding):
- `dispatch/runtime-guards.ts` `GuardBinding` (input of `controllerGuards(binding): RuntimeGuards`) gains `routeWindow?: (order: WorkOrder) => number | undefined | Promise<number | undefined>` (the routing table's `contextTokens` for `order.route`) and `context.blockUnknownWindow?: (principal: Principal, command: { taskId: string; attemptId?: string; route: string; what: string }) => Promise<{ blockerId: string; reason: string }>` (called with `binding.system`; `what` says what was refused, e.g. first call / stored conversation). `binding.window(order)` stays the host's figure and is used first when it is a positive integer.
- `RuntimeGuards["context"].admit(...)` resolves `{ admit: boolean; reasons: readonly string[]; retryable?: boolean }`. With no window from either figure: `{ admit: false, retryable: false, reasons }` without calling `context.admit`, the reasons name the route and say its window must be set (contain `window` and `set`), and `blockUnknownWindow` is called once per refusal with the order's `taskId` and `route`. `resume(order, storedTokens: number)` (signature unchanged) then answers `{ resume: false, ... }` and calls `blockUnknownWindow` too. With a known window both are judged as before against it (the `ctx-admission` record carries that `window` and `routeName`; base wording such as `over the startup limit of 1024 for a 4096-token window` and `30000 tokens, over 2457 (60% of this model's 4096)` is unchanged).
- If `routeWindow` throws/rejects, `admit` rejects with that error and no blocker is opened.
- A route name not of the routing table's `provider/model` shape appears in reasons and blocker as `quoted(route)` (status/explain.ts); `provider/model` names may appear plain or quoted.
- `ContextEnforcementService.blockUnknownWindow` (context/enforcement.ts) opens one open `context_overflow` blocker per task (a second call returns the open one); its summary names the route and both places to set the window: the routing table's `contextTokens` (that word) and the local host's own window figure (the word `host`).
- `LocalWorker` (dispatch/local-worker.ts): with `guards.context` present and `order.resumeFrom` set, the stored size is `guards.context.storedTokens?.(from)`, else (absent or answering `undefined`) the worker package's checkpoint shape `from.nn.contextTokens` (a non-negative integer); with neither, the runtime is opened with no `from`, the agent's note in the first prompt contains `not resumed`, and `onGuardError(attemptId, "resume decision", error)` is called once. A reader's figure, when given, decides. Without `guards.context` the checkpoint is resumed as before. An `admit` result with `retryable: false` ends the attempt `failed` after one round with no `compact()` call.
- `api/dispatch-compose.ts` / `startController({ dispatch: { local: { window, storedTokens?, build } } })`: the guards handed to `build` (`services.guards.context`) use the routing table (`routing.get()` → `routes[route].contextTokens`) as `routeWindow`, always have `storedTokens` (the embedder's `local.storedTokens`, else a reader of the `{ nn: { contextTokens } }` shape answering `undefined` for anything else), and `rebuildView` (C07g) uses the same window rule (a host figure of 0 falls back to the table's window, so no blocker is opened).
