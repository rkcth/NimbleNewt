Build the three items the Acceptance names (the rest are a follow-up; say which you left):
(1) a Stop of an agent, team or the installation walks the swarm descendants of their tasks (today only a task's Stop does), and holds the swarm children it ended from being started again;
(2) the stop-charge sweep's window is not starved: 2000 settled entries listing a blocked Stop do not keep a later unpaid charge from being paid;
(3) a task's stop_cleanup view finds a Stop made through its agent, team, swarm parent or the installation, and says which scope the figures come from; a wider stop made before the task existed or was given to that agent is not its answer.
A Force Stop records the pause it holds by, so once resumed and merely paused again it no longer holds swarm children.

RULES: owner controls are reachable by free-form chat (CHAT_OPS in chat/commands.ts, STATUS_KINDS in status/status.ts; no magic words; nothing tells the owner to say a phrase). Agent-written text shown to the owner is escaped (quoted() in status/explain.ts). Windows-safe code. Tests: each file under 600 s; use the existing scripted test harnesses (lifecycle/stop-suite.ts); no real network. In lifecycle/dispatch-ports.ts, dispatchStopPorts gains an optional `descendantsOf(taskIds)` hook (without it each root is walked on its own and the results merged).

CONTRACT (the acceptance tests check exactly these; names, fields and wording here are binding):
- lifecycle/dispatch-ports.ts: the last (`more`) argument of `dispatchStopPorts` gains `descendantsOf?: (taskIds: readonly string[]) => Promise<{ readonly ids: readonly string[]; readonly truncated: boolean }>` (the same result shape as the existing `descendants(taskId)`: the tasks below ANY of the roots, deduplicated). For an `agent`, `team` or `installation` scope the tasks the scope's own live attempts run (`dispatcher.get(principal, attemptId)?.taskId`) are passed to it together, in one call per walk. Without `descendantsOf`, `descendants` is called for each of those tasks and the results merged. A `lifecycle/index.ts` export `swarmDescendantsOf(storage, taskIds, max?)` (same result shape) is wired in api/start.ts.
- For those wider scopes the children's work is handled as a task's Stop already handles it (base L02d behaviour): each live attempt of a child task is an inventory item `{ kind: "child", ref: <attemptId>, state: "running" }`; the children's jobs are listed and asked to stop (`cancelJob`); `terminate` stops the children's attempts; a child task for which `mayControl(by, taskId)` is false is not stopped, its jobs are not asked and its attempt is not ended by Force Stop (`local.end`), and `unresolved` names it (`child <taskId>: not stopped, <by.id> may not control it`); a truncated walk is the item `{ kind: "child", ref: "swarm:descendants-truncated", state: "unknown" }`. The scope's own attempts are always allowed.
- lifecycle/stop.ts `StopService.holding(taskId: string, child?: string, options?: { readonly wider?: boolean })`: without `wider` unchanged (only the task's own request). With `wider: true`, a Stop/Suspend of any scope whose pause blocks the task (its agent, a team above it, the installation) also holds, on the same conditions as the task's own (not cancelled, its pause is the gate's current cause, `mayHold(requestedBy, child)` true); a resume of that scope lets go. dispatch-compose's swarm-ancestor check uses `wider: true`.
- `StopService.force` records the pause request it holds by (`gateRequestId`, like `request` does), so after a resume and a plain `pause` of the same scope the finished Force Stop no longer holds (own or `wider`).
- `StopService.cleanupSpend(viewer, scope)` result gains `through?: { kind: string; id: string }` and `requestedAt?: string` (the request's `requestedAt`). When no request exists for exactly the scope, the latest (newest `requestedAt`) request of a covering scope is returned with `through` naming that scope (`{ kind: "installation", id: "installation" }` for the installation): a task is covered by its assignee agent, the teams above that agent, its swarm parents (the `swarm-link` record `{ parentTaskId }`, walked up) and the installation; an agent by its teams and the installation; a team by parent teams and the installation. A covering request is skipped when it was asked before the scope's record was created, or (agent or team request, task scope) before the task's current assignment generation was created, or when the viewer may not control that covering scope (then `undefined`, never an error). A request of the scope itself is always the answer and has no `through`. Figures (`spent`, `attempts`, ...) are the wider request's.
- status/status.ts `stop_cleanup`: when `through` is set the lines name that scope as `<kind> <id>` (e.g. `agent agt-b`, id shown escaped through `shown()`/quoted text like every record text, no raw control characters), still mention the scope asked about, every line cites a record, and some line cites `{ kind: through.kind, id: through.id }` and the request `{ kind: "stop", id: intentId }`.
- The stop-charge sweep (`StopService.sweep` -> retry of charges) takes an open entry off the index when its charge is made and nothing more is wanted, even while a request it lists is unfinished (blocked); so with 2000 such entries ahead, a later failed charge is paid within a few sweeps and that request's "cleanup spend not charged" mark is then cleared. The blocked request stays blocked.
