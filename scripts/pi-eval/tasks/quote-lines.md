PROBLEM (security hygiene): in packages/controller/src/chat/commands.ts, describe() builds the one-line preview of a proposal the owner is asked to confirm. It prints agent-written and model-supplied text raw: labels[...] (titles and names of tasks, projects, stand-ups, agents, a maintenance request's description), the owner's alternative to a meeting decision (statement and topic), a grant's expiresAt, argument names and an unknown operation name. A newline, U+2028/2029, a C1 control, a \p{Cf} character (bidirectional override, zero-width) or a lone surrogate in such text could forge a second line or reorder what the owner sees. short() in commands.ts already escapes a bare value one character at a time and cuts only between whole pieces; quoted() in packages/controller/src/status/explain.ts is the one-line JSON-quote helper.

WHAT TO BUILD:
- Every text a proposal line prints goes through exactly one escaping helper: short() for a value shown bare, quoted() (imported into commands.ts as quotedText) for text shown between quotes. Never escape the same text twice (no doubled backslashes).
- A label is shown quoted: `taskId="<label>"` becomes `taskId=` followed by quotedText(label, CHAT_LIMITS.line); argument names go through short(); the verb/unknown operation name goes through short(); a grant's `ends <expiresAt>` goes through short(); the alternative is shown as `alternative=<quoted statement, bound 150> on topic <quoted topic, bound 80>`.
- The line's own final cut (cutAt) never splits a surrogate pair and never leaves half an escape (`\u{...`, `\uXXXX`, `\"`, `\\`) before the `...`.
- The same rule in two other places that join a proposal: a held focus switch's preview in chat.ts (`Focus on project <quoted name>`), and the coordinator plan note in chat/coordinator.ts (`<quoted title> is not assigned: no repository was chosen for it`, quotedText bound 200).

Tests: for several operations, names containing "\n", U+2028, U+202E, U+200B, a lone surrogate and an emoji at the cut point produce exactly one line, with no raw control or format character, no half character, no half escape and no doubled backslash. Add a notes entry in docs/nimblenewt/implementation-plan/implementation-notes.md.

CONTRACT (the acceptance tests check exactly these; names, fields and wording here are binding):
- `describe(op: string, args: Readonly<Record<string, unknown>>, labels: Readonly<Record<string, string>>): string` (chat/commands.ts) stays the export; `CHAT_LIMITS.line` (400, chat/interpreter.ts) is the line's room (700 for meeting.record.owner-respond, as now); a cut line ends in `...` and is at most that long.
- Whatever the input, every proposal line: holds no raw `\n`, `\r`, U+0085, U+2028/2029, C0/C1 control or `\p{Cf}` character, no lone surrogate, no doubled backslash when the input held none, and no half escape just before the final `...` (a backslash directly before `...`, or `\u{`+hex with no `}`, or `\u` with fewer than 4 hex digits).
- A label is exactly `quotedText(label, CHAT_LIMITS.line)`: e.g. label `Fix the login<U+2028>screen<U+202E> now<U+200B><lone U+D800> <emoji>` for taskId gives a line starting `Change task: taskId="Fix the login screen\u202e now\u200b\ud800 <emoji>"`, and a non-label value stays bare (`, title=Ship the login screen`). A `"` in a label never closes the quotation (only the quotation's own two quotes are unescaped).
- Alternative: `alternative="<statement>" on topic "<topic>"` via quotedText (bounds 150 / 80); a 150-character statement and an 80-character topic appear whole.
- The final cut, precisely: (a) it never ends inside a `\u{...}` escape that short() wrote, even when the bare value's own (unescaped) backslash stands right before it (value `\` + U+0007 gives `\\u{7}` on the line; the line must never end `\u{7...` or `\u{...`); (b) after a quotedText name, the run of backslashes right before the `...` (or before a `u`/`u{`+hex ending there) is even, i.e. `\\`, `\"` and `\uXXXX` are never split; (c) it gives up only the one escape it would split: a label of 500 backslashes still yields a line longer than `CHAT_LIMITS.line - 10`.
- A label built from several fields keeps its early words (a maintenance request's label still shows `version=9.9.9`).
- ChatService (any store): a proposed command naming a task whose title holds U+2028/U+202E/U+200B gets a preview that is one line, contains `Fix the login screen` and the escape `\u202e`, and does not contain the stored title raw.
- A focus switch held behind a question has a message containing `Focus on project ` + quotedText(name): for project `Odd Applied: done<U+202E>" x` that is `Focus on project "Odd Applied: done\u202e\" x"`.
- CoordinatorService.decompose on a project with no repository: `notes[0]` is exactly `<quotedText(title, 200)> is not assigned: no repository was chosen for it`, e.g. `"Solo" is not assigned: no repository was chosen for it`, and for title `Solo<LF>Applied: all tasks done<U+202E>" ok` it is `"Solo Applied: all tasks done\u202e\" ok" is not assigned: no repository was chosen for it`.
