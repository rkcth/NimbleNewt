# G09 evidence: retained-context inquiry and mid-generation interruption (2026-10-22)

Card G09 asks for actual NimbleNewt component and integration tests, not a parallel state machine. Everything below runs the production services: C05 `ContextBranchService`, L05 `GenerationService`, H04 `InquiryService`, C04 `ContinuationService`, with the production Pi adapter (F06b/F06c/F06d) over durable JSONL storage and the scripted offline provider the adapter tests already use. No network is used; the tests run under `scripts/offline-guard.mjs`.

- Code under test: implemented in the commit that adds this file (the lead appends the hash). Before that commit the base was `9be98d4` plus the working tree.
- Tests: `packages/integration/src/g09-retained-context.test.ts` (5 scenarios, each run on all four controller backends: reference store, SQLite, SQLite on a worker thread, PostgreSQL = 20 tests), with glue in `g09-fixture.ts`; `packages/pi-adapter/src/model-change.test.ts` (1); `packages/controller/src/continuation/continuation.test.ts` (4, extended).
- Reproduce: `npx tsc --build`, then `node --import ./scripts/offline-guard.mjs --test --test-timeout=600000 packages/integration/dist/g09-retained-context.test.js packages/pi-adapter/dist/model-change.test.js packages/controller/dist/continuation/continuation.test.js`.

## The fixture

`g09-fixture.ts` is glue only: it builds the services, opens a Pi adapter on a directory that outlives the adapter, records the exact manifest of every model request (`role: text` per message, in order), and mirrors the adapter transcript's text into the task's controller history so that the controller's fork (C05) and the adapter's fork (F06b) can be compared at the same boundary. Phases are driven by calling the services (`ask`, `open`, `branch`, `suspend`, `restore`, `resume`, `applyUpdates`, `interrupt`, `correct`, `admitEffect`); the fixture keeps no state of its own about branches, holds or resumes.

## Acceptance sentence to proof

| Acceptance text | Scenario (test name starts with) | What is asserted |
|---|---|---|
| Inquiry sees original current context without polluting parent | "an inquiry sees the original current context exactly" | The provider's request for the inquiry is exactly `[system, user: do the task, assistant: <call echo>, toolResult: TOOL-SENTINEL-42, assistant: task answer, user: How is it going?]`. The controller branch inherits exactly the two parent history entries (throughSeq 2). Before and after the inquiry the parent transcript, the task history and the assignment are byte-identical; the inquiry's entries exist only in the branch. H04: inquiry `answered`, generation unchanged. |
| Unchanged resume correct | same test | `resume` returns the destination; the parent's next request is exactly its original context plus the new instruction; no `nimblenewt.update` entry exists. |
| Updated resume correct | "an updated resume applies the selected update once" | `applyUpdates` is applied once (replay by command ID reports `replayed`, a second command for the same content is refused); the parent receives the update once with the source entry in its data; a repeated submission does not ask the model again; the parent's request holds the original context, the old decision, then the correction, and nothing from the inquiry. |
| Stream interruption and partial tool calls cannot admit stale actions | "a stream cut in the middle of a tool call's arguments", "a correction landing between a complete tool call and its execution" | Slow scripted stream aborted inside the arguments (the aborted transcript entry shows the call id, so the test cannot pass vacuously): the tool never runs, the L05 call is `dropped`, a late completion is recorded as late and not applied, admission is refused before and after the hold is lifted, the aborted turn is not a fork point and the partial call is absent from the next request. A correction between a complete call and its execution: the adapter tool's admission is refused (`interrupted`), the outside world is never touched, the model is told the refusal, and the corrected generation then acts once. A pause (finish and hold) keeps a complete call `held` until it is released and admitted again on purpose. |
| Context survives restart without summary reconstruction | "the context survives a restart and a change of provider" | Adapter closed and reopened on the same JSONL directory: the transcript is deep-equal to before, contains no compaction or summary entry; a suspended branch is restored through restarted controller services with `exact: true` and zero extra entries, and its history is identical. |
| Continuity across a provider change | same test | The conversation is moved to a different provider with the adapter's new `useModel`; the new provider's first request is exactly the old context plus the new instruction; the old provider's last request had the same prefix. Without `useModel` the reopened conversation answers `unanswered/no_model` and asks nothing. |
| Correction of an old owner decision | "an updated resume ..." and the restart scenario | A superseding desk record is applied to the branch once and reaches the parent after the old decision it corrects; decision A was applied to the branch first and then shows as `changed` once B supersedes it, B is applied once; L05 `correct` raises the context revision so a response begun on the old decision cannot be admitted (`interrupted`) and a new generation bound to the old revision is refused (`stale`). After a restart and provider change a placed correction appears in the new provider's request in order: old context, earlier turn, correction, new instruction. |
| Resume record labels native restore, reconstruction or restart | restart scenario, plus the C04 test | `ContinuationService.resume` takes `restoredBy: native-restore | reconstruction | restart`, stores it on the resume record, returns it, treats it as part of the command's identity, refuses other values, and records nothing when it is not given. The scenario records `native-restore` only after the adapter verified the checkpoint on the reopened storage; against an empty storage the checkpoint is rejected (`unknown_entry`), a reconstruction from mirrored history is shown to differ from the original context, and those resumes are labelled `restart` and `reconstruction`. |

## Mutation checks (each makes at least one named test fail; restored afterwards)

Branch entries written into the parent's history (4 fail); update dedupe removed (4); interrupted-run check in `#blocked` removed (12); hold check in `#blocked` disabled (4, after the pause case was added); partial call kept `complete` on cancel (4); `useModel` made a no-op (4); the resume label not stored (4). Not-tracking a partial tool call as open in `turnBoundaries` is now caught (the test removes the pending input and expects no boundary). Counting an aborted turn that has no tool call as a boundary is still not caught here; the adapter's own `turnBoundaries` tests cover that rule.

## What this proof does not show

- The adapter has no stream event subscription. The partial-call test records a stand-in chunk in L05 (`{"payload":"xxxxxxxx`), unrelated to what Pi actually streamed: the L05 half and the adapter half are shown side by side (both cut, both refuse, neither admits), not wired together. The abort landing inside the call is checked from the aborted entry; the wait before the abort is a short delay after the provider received the request.
- No production code carries a C05 `resume` or `applyUpdates` result into the adapter conversation. Scenario 2 copies the update text into `parent.submit`, and decision A in Pi and on the desk are linked only by the test, so "updated resume applied once" is C05's dedupe plus the adapter's request-ID dedupe joined by test glue. In the complete-call scenario the adapter tool calls L05 admission and execution, which is the intended wiring; no production dispatcher does that yet (H12/T01).
- Reconstruction is shown by a fixture that rebuilds a prompt from mirrored history; no production reconstruction exists, and Pi has no portable export. The label is the host's statement; the host rule used here (checkpoint verified on the reopened storage means native restore) is the fixture's.
- `useModel` moves one conversation; branches keep the model they were created with. No audit event is emitted for it yet.
- Hashes of the code under test are the working tree; no commit exists yet.
