# Implementation notes and known limitations

Running record of limitations found while implementing task cards. Each entry names the card that should resolve it.

- **Install scripts (resolved in F03):** `.npmrc` sets `ignore-scripts=true`; `@google/genai` (a no-op preinstall) and `protobufjs` (postinstall) never run their scripts and all tests pass. Enabling any install script needs a reviewed change; the license inventory marks affected packages.
- **Minimum Node (F03):** `engines` requires Node >=22.19.0 and `@types/node` is pinned to 22.x. CI runs 22.19.0 and 24.21.0 on Linux, macOS and Windows. Only Node 24.21.0 on Linux has been run locally; the CI matrix has not yet executed because the workflow has not run on GitHub.
- **Database isolation is convention (F01):** the boundary check restricts package dependencies and imports, but does not forbid built-ins such as `node:sqlite` inside `pi-adapter`.
- **Offline guarantee (F03):** `scripts/offline-guard.mjs` is preloaded into every package test process and blocks non-loopback `fetch`, sockets, DNS and UDP; Worker threads and Node child processes inherit it. It is a tripwire, not a sandbox: non-Node child processes and native code are not covered. The Linux CI job therefore reruns the suite inside a network namespace (`unshare --net`). That CI step, and all macOS/Windows and Node 22.19.0 (npm 10) cells, are unverified until the workflow has run on GitHub; F03 acceptance needs a green run of all six matrix cells. A Node child started with an explicit `env` that omits `NODE_OPTIONS` runs unguarded; when F05 adds tool tests, check how Pi Durable spawns tool processes (the Linux namespace rerun covers it there).
- **Test-only dependencies (before F05):** the boundary check requires every imported package to be a runtime dependency. Fix it so test files may import `devDependencies` if F05 introduces test-only packages.
